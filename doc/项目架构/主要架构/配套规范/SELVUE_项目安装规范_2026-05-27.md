# SELVUE 项目安装规范

## 1. 文档目的

本文档用于约束 `SELVUE` 多工程宿主的项目安装方式。  
目标是保证后续新增 `src/projects/xxx` 工程时满足以下能力：

- 装上工程目录即可被宿主自动发现并使用
- 移除工程目录后宿主仍可正常启动
- 宿主层不需要为某个具体工程写死判断或硬编码引用

本文档适用范围：

- `C:\opt\workspace\SEL\SELATTENDANCE\SELVUE\src`
- `src/projects/*`
- `src/App.vue`
- `src/projects/index.js`

---

## 2. 核心原则

### 2.1 宿主只认注册入口，不认业务目录细节

宿主层只通过：

- `src/projects/index.js`
- `import.meta.glob('./*/index.js', { eager: true })`

自动发现工程。

宿主不允许直接引用：

- `src/projects/attendance/...`
- `src/projects/memory/...`
- 任何未来具体工程目录

也就是说，宿主只知道“工程注册对象”，不知道某个工程内部如何组织。

### 2.2 工程以目录为安装单元

每个子工程必须是一个独立目录，例如：

```text
src/projects/attendance
src/projects/memory
```

安装工程的定义是：

- 将该工程完整目录放入 `src/projects/`

移除工程的定义是：

- 将该工程完整目录从 `src/projects/` 删除或移走

禁止通过修改宿主源码来完成“安装”或“卸载”。

### 2.3 宿主必须允许“部分工程缺失”

宿主必须接受以下场景：

- 只有 `attendance`
- 只有 `memory`
- 同时有 `attendance` 和 `memory`
- `src/projects/` 下暂时没有任何工程

其中：

- 有工程时：宿主正常加载第一个可用工程或 URL 指定工程
- 无工程时：宿主显示空状态页面

---

## 3. 工程目录规范

### 3.1 最小目录结构

每个工程至少满足：

```text
src/projects/<project-id>/
  index.js
  views/
    <ProjectRootView>.vue
```

推荐最小增强结构：

```text
src/projects/<project-id>/
  index.js
  style.css
  views/
    <ProjectRootView>.vue
  components/
  composables/
  services/
  constants/
```

说明：

- `index.js` 是唯一强制注册入口
- `views/` 用于工程根页面
- `style.css` 可选，但推荐存在
- 其余目录按工程复杂度逐步扩展

### 3.2 目录命名规则

`src/projects/` 下的目录名必须与工程 id 语义一致，例如：

- `attendance`
- `memory`

推荐规则：

- 全小写
- 英文
- 如需分词，优先使用短横线或单词直连，但要与 `id` 保持一致语义

不建议：

- 中文目录名
- 临时目录名
- 与工程用途无关的抽象命名

---

## 4. index.js 导出契约

### 4.1 必须导出 default 对象

每个工程的 `index.js` 必须默认导出一个注册对象。

标准形式：

```js
import ProjectRootView from './views/ProjectRootView.vue'
import './style.css'

export default {
  id: 'memory',
  label: 'Memory',
  description: 'Memory workspace starter module',
  order: 20,
  component: ProjectRootView
}
```

### 4.2 字段要求

必须字段：

- `id`
  含义：工程唯一标识
- `label`
  含义：宿主切换器显示名称
- `component`
  含义：工程根组件

推荐字段：

- `description`
  含义：工程说明
- `order`
  含义：宿主显示顺序，数字越小越靠前

### 4.3 字段约束

`id` 约束：

- 必须唯一
- 必须稳定
- 不允许和其他工程重复

`label` 约束：

- 面向用户显示
- 应简短明确

`component` 约束：

- 必须是可直接渲染的 Vue 组件
- 必须是当前工程自己的根入口视图

`order` 约束：

- 可选
- 不写时按宿主默认排序靠后处理

### 4.4 禁止事项

禁止在 `index.js` 中：

- 直接操作宿主状态
- 修改 `App.vue`
- 引用其他工程的根组件
- 写死对 `attendance` 或 `memory` 的条件判断

`index.js` 的职责只有一件事：

- 把当前工程注册给宿主

---

## 5. 宿主发现规则

### 5.1 自动发现方式

宿主统一通过：

```js
import.meta.glob('./*/index.js', { eager: true })
```

扫描 `src/projects/` 下所有一级子目录的 `index.js`。

因此，工程要想被宿主发现，必须满足：

1. 目录位于 `src/projects/<project-id>/`
2. 目录下存在 `index.js`
3. `index.js` 默认导出合法注册对象

### 5.2 宿主过滤规则

宿主会过滤掉不合法工程注册对象。

无效对象包括：

- 没有 `id`
- 没有 `component`
- `default export` 缺失

这类目录存在时：

- 不应拖垮宿主
- 但该工程不会被纳入可用列表

### 5.3 激活规则

宿主当前激活工程的解析顺序应保持为：

1. URL 中的 `project` 参数
2. 第一个可用工程
3. 若没有任何工程，则显示空状态

例如：

- `?project=attendance`
- `?project=memory`

如果 URL 指向的工程已被移除：

- 宿主必须自动回退到第一个可用工程
- 不能因为 URL 残留失效值而报错

---

## 6. 宿主切换规则

### 6.1 切换器职责

宿主层可以提供工程切换 UI，例如下拉框。  
切换器职责仅限于：

- 展示当前可用工程列表
- 切换当前激活工程
- 将激活工程写回 URL

### 6.2 切换器数据来源

切换器必须只使用：

- `availableProjects`

禁止：

- 自己手写工程列表
- 在 `App.vue` 中写死 `attendance`、`memory` 选项

### 6.3 切换器容错

当只有一个工程时：

- 可以隐藏切换器

当多个工程并存时：

- 切换器应自动显示

当某工程被删除后：

- 切换器列表自动消失该项
- 宿主自动回退到剩余可用工程

---

## 7. 样式与资源规范

### 7.1 工程样式入口

每个工程推荐有自己的：

- `style.css`

由工程自己的 `index.js` 主动引入：

```js
import './style.css'
```

这样可保证：

- 工程装上时样式自动生效
- 工程移除时样式自动随目录一起消失

### 7.2 公共资源放置

跨工程共享的内容必须进入：

```text
src/shared/
```

例如：

- `shared/components`
- `shared/services`
- `shared/constants`
- `shared/theme`

禁止把公共能力放在某个具体工程目录下再被其他工程反向引用。

错误示例：

- `memory` 引用 `attendance/services/request.js`
- 宿主引用 `attendance/components/...`

正确做法：

- 提取到 `shared/`

### 7.3 工程私有资源放置

只属于某个工程的内容必须留在该工程目录下，例如：

- 该工程专用页面
- 该工程专用 composable
- 该工程专用样式
- 该工程专用 service

这样删除整个工程目录时，相关资源会一起拔掉，不会污染宿主。

---

## 8. 禁止事项

以下行为一律禁止：

### 8.1 宿主硬编码具体工程

禁止在宿主中写：

- `import AttendanceWorkbenchView from ...`
- `import MemoryWorkbenchView from ...`
- `if (project === 'attendance')`
- `if (project === 'memory')`

### 8.2 工程之间直接互相依赖

禁止：

- `attendance` 直接引用 `memory` 内部模块
- `memory` 直接引用 `attendance` 内部模块

工程之间不允许横向耦合。

### 8.3 以“改宿主”作为安装动作

禁止以下流程：

1. 新建工程目录
2. 再去改 `App.vue`
3. 再去改宿主开关逻辑

正确流程必须是：

1. 放入 `src/projects/<project-id>/`
2. 提供合法 `index.js`
3. 宿主自动发现

### 8.4 在 shared 中放工程私有业务

禁止把只属于某一个工程的业务代码放进 `shared/`。

判断标准：

- 如果删除该工程后，这段代码也应随之消失
  那它就不属于 `shared`

---

## 9. 新工程安装步骤

新增一个可插拔工程时，必须按以下步骤执行：

1. 在 `src/projects/` 下创建新目录
2. 新增 `index.js`
3. 新增根页面组件
4. 可选新增 `style.css`
5. 如有工程私有逻辑，再补 `components / composables / services`
6. 执行前端构建验证

最小示例：

```text
src/projects/report/
  index.js
  views/
    ReportWorkbenchView.vue
  style.css
```

最小 `index.js` 模板：

```js
import ReportWorkbenchView from './views/ReportWorkbenchView.vue'
import './style.css'

export default {
  id: 'report',
  label: 'Report',
  description: 'Report workspace module',
  order: 30,
  component: ReportWorkbenchView
}
```

---

## 10. 工程卸载步骤

卸载一个工程时，必须按以下步骤执行：

1. 删除或移走 `src/projects/<project-id>/`
2. 不修改宿主硬编码
3. 重新执行前端构建验证

卸载后的期望结果：

- 宿主继续可启动
- 切换器不再显示该工程
- URL 若仍指向该工程，则自动回退到首个可用工程

---

## 11. 验证要求

每次新增或移除工程后，至少验证：

### 11.1 安装验证

- 工程能被宿主自动发现
- 切换器能显示该工程
- 选择该工程后能正常渲染根页面

### 11.2 卸载验证

- 删除该工程目录后构建仍通过
- 宿主不报找不到模块
- 切换器自动移除该工程

### 11.3 构建验证

必须执行：

```bash
npm run build
```
