# attendance + uniauth 模块细粒度权限码清单

## 1. 文档定位

本文档只服务当前真实项目：

- `attendance`
- `uniauth`

本文档用于统一：

- 菜单权限码
- 模块访问权限码
- 按钮 / 动作权限码
- 数据范围权限码
- 特殊业务权限码

## 2. 编码原则

### 2.1 统一格式

权限码统一使用小写点分格式：

```text
{system}.{module}.{action}
```

示例：

- `attendance.employee.view`
- `attendance.employee.create`
- `attendance.monthly.close`
- `uniauth.role.assign_permission`

### 2.2 system 取值

- `attendance`
- `uniauth`

### 2.3 action 取值建议

常用动作统一优先使用：

- `view`
- `create`
- `update`
- `delete`
- `export`
- `import`
- `approve`
- `reject`
- `recalculate`
- `close`
- `reopen`
- `assign`
- `bind`
- `retry`
- `manage`

不要同义混写，例如：

- 不要一会儿 `edit` 一会儿 `update`
- 不要一会儿 `remove` 一会儿 `delete`
- 不要一会儿 `list` 一会儿 `view`

## 3. 数据范围码

数据范围不建议混进普通按钮权限码，建议作为独立范围值：

- `ALL`
- `TENANT`
- `DEPARTMENT`
- `WORKPLACE`
- `SELF`

建议 token 中以 `data_scopes` 数组输出。  
建议数据库中用独立字段或独立关系表达，不要把它和普通菜单权限混成一类。

## 7. 推荐数据库表达

建议最少包含这些关系：

- `user`
- `role`
- `permission`
- `menu`
- `user_role`
- `role_permission`
- `role_menu`

如果要做数据权限，再补：

- `role_data_scope`

## 8. 推荐 token claim

建议 token 中至少输出：

- `user_id`
- `username`
- `tenant_code`
- `role_codes`
- `permission_codes`
- `menu_codes`
- `data_scopes`

## 9. 前后端接入约束

### 9.1 前端

- 菜单按 `menu_codes` 控制
- 按钮按 `permission_codes` 控制
- 数据范围提示按 `data_scopes` 控制

### 9.2 后端

- controller / interface 权限按 `permission_codes`
- 数据查询范围按 `data_scopes`
- 租户隔离按 `tenant_code`

## 10. 第一批必须优先接的权限

如果不想一上来铺太大，第一批优先接这些：

- `attendance.employee.view`
- `attendance.employee.create`
- `attendance.employee.update`

## 11. 当前结论

当前项目不能只停留在：

- 是否登录
- 是否管理员
- 是否能看一个大模块

正式权限体系必须继续下沉到：

- 模块
- 菜单
- 按钮 / 动作
- 数据范围
- 特殊业务动作

只有这样，`attendance + uniauth` 才能真正形成可运营的第9阶段权限体系。
