# SELSP 自动bug修复接入规范

## 1. 文档定位

本文档用于规定 `SELATTENDANCE/SELSP` 后续接入自动 bug 修复能力时，Java 后端工程必须满足的基础条件和实施规范。

自动修复链路中的目录定位、分层判断和最小修复范围，必须优先基于：

- `/Users/showfolder/Documents/workSpace/SELF/SELATTENDANCE/SELSP/src/main/java/com/sp/selfsp/attendance`
- 不再以 `SELTEMPLATE` 的旧模板目录推断当前项目真实结构

目标不是直接定义某一种自动修复算法，而是先把工程改造成“适合被自动诊断、自动测试、自动修复、自动回归”的结构。

## 2. 接入目标

SELSP 接入自动 bug 修复能力后，至少要支持：

- 自动定位问题模块
- 自动关联日志与测试
- 自动构造最小修复范围
- 自动执行回归验证
- 自动判断修复是否生效

## 3. 工程前置条件

在接入自动 bug 修复前，工程必须具备以下前置条件：

1. 模块边界清晰
2. 包结构稳定
3. 统一响应结构
4. 统一异常处理
5. 统一日志字段
6. 统一配置入口
7. 可执行测试
8. 可重建测试数据

如果以上条件不成立，自动修复只能停留在不稳定试错层，无法形成可靠闭环。

## 4. 日志接入要求

自动 bug 修复依赖日志做初步定位，因此必须满足：

- 每次请求具备 `traceId`
- 关键失败具备稳定 `errorCode`
- 关键动作具备稳定 `module` 和 `action`
- 系统异常具备异常类型和堆栈

接入要求：

- 日志字段命名必须统一
- 访问日志、业务错误日志、系统错误日志必须可区分
- 不允许关键日志缺失上下文

## 5. 测试接入要求

自动 bug 修复能否可靠，核心取决于测试闭环。

必须满足：

- 至少存在可执行的 API 测试
- 问题出现后可以补最小复现测试
- 修复后可以补目标回归测试
- 相邻路径可以做最小回归

推荐分层：

- Controller / API 测试
- Service 测试
- DAO / SQL 测试
- 启动与配置验证

## 6. 配置接入要求

自动修复链路通常会在不同环境重复执行，因此必须满足：

- 配置统一收口
- 默认使用相对路径
- 不写死机器绝对路径
- 测试环境和运行环境可独立切换

特别要求：

- 日志目录、缓存目录、测试目录、文档目录都必须可配置
- 机密配置不得硬编码进仓库

## 7. 模块边界接入要求

自动 bug 修复必须知道“问题属于哪个模块、哪一层、哪个职责边界”。

因此要求：

- Controller、Service、DAO 分层清晰
- 模块语义稳定
- 输入对象、输出对象、领域对象分离
- 公共能力与业务能力分离

禁止：

- 一个类跨 Controller/Service/DAO 多重职责
- 一个模块同时塞多个不相关领域

## 8. 缺陷定位输入要求

后续自动修复入口应优先接受以下输入：

- 报错日志
- traceId
- 错误码
- 失败接口
- 失败测试
- 失败 SQL

目标是让系统先定位：

- 哪个模块
- 哪个动作
- 哪一层
- 哪个测试最相关

再进入修复动作，而不是直接全仓库盲改。

## 9. 自动修复执行边界

自动 bug 修复默认只应修改：

- 明确命中的模块
- 明确命中的层
- 与当前缺陷直接相关的配置或测试

禁止：

- 无边界地跨多个无关模块一起大改
- 在没有复现证据时直接大面积重构
- 只修主路径不做相邻回归

## 10. 自动修复验证闭环

自动修复完成后，至少要形成三类验证：

1. 复现验证
2. 修复验证
3. 相邻回归验证

如果缺少其中任一项，都不应视为自动修复完成。

## 11. 推荐闭环流程

建议固定流程：

1. 读取失败日志 / traceId / 测试结果
2. 判定问题模块和问题层
3. 构造最小复现测试或失败证据
4. 生成修复方案
5. 执行最小改动
6. 运行目标测试
7. 运行相邻回归测试
8. 输出修复结论和剩余风险

## 12. 文档与经验接入要求

自动 bug 修复不应只依赖代码和日志，还应能够读取：

- 通用架构标准
- 模块专项设计文档
- 日志模板规范
- 包结构与命名规范
- 已有经验记录

因此要求：

- 通用文档必须长期保持稳定
- 专项文档必须和代码边界一致
- 经验记录必须可检索

## 13. 当前阶段的最低接入标准

当前 SELSP 若作为自动 bug 修复准备阶段，最低要求是：

- 所有新模块必须按标准目录创建
- 所有核心接口必须接入统一日志和异常
- 所有高风险变更必须有可执行测试
- 所有正式配置必须从统一配置入口读取
- 所有文档必须明确“通用标准”和“专项设计”的边界

## 14. 后续升级路线

建议按以下顺序升级：

### 14.1 第一阶段

- 统一日志字段
- 统一测试入口
- 统一模块目录
- 统一配置入口

### 14.2 第二阶段

- 增加错误分类码
- 增加缺陷到测试的映射
- 增加自动回归脚本
- 增加模块专项诊断文档

### 14.3 第三阶段

- 增加自动缺陷定位器
- 增加自动修复候选方案生成
- 增加自动回归判定
- 增加修复经验自动沉淀

## 15. 执行要求

以后凡是声称“已接入自动 bug 修复能力”的模块，至少应满足：

1. 有统一日志
2. 有统一异常
3. 有可执行测试
4. 有可重建测试数据
5. 有清晰模块边界
6. 有专项设计或接口文档

其中接口文档目录约定：

- `SELSP` 工程的接口文档默认落在 `doc/aip接口文档/`
- 若模块以接口文档作为自动修复输入材料之一，应优先从该目录读取，而不是在 `doc/` 根目录随机检索

否则只能叫“具备自动 bug 修复准备条件不足的初始模块”，不能叫真正可接入模块。
