# SELSP 日志字段统一模板

## 1. 文档定位

本文档用于统一 `SELATTENDANCE/SELSP` 所有 Java 模块的日志字段、日志分类和日志模板。

日志字段命名、模块语义和 trace 组织应优先参照：

- `/Users/showfolder/Documents/workSpace/SELF/SELATTENDANCE/SELSP/src/main/java/com/sp/selfsp/attendance`

目标是让日志同时服务于：

- 人工排障
- 自动 bug 定位
- 自动回归验证
- 跨模块问题关联

## 2. 日志设计原则

统一日志必须满足：

- 一次请求可追踪
- 一个失败可归类
- 一个问题可关联测试和代码
- 多模块日志可统一检索

日志内容必须优先表达业务语义和排障价值，不写无意义文本。

## 3. 强制通用字段

所有正式日志至少应具备以下通用字段：

- `timestamp`
- `level`
- `traceId`
- `logger`
- `message`

推荐扩展字段：

- `module`
- `action`
- `status`
- `durationMs`
- `operator`
- `resourceId`
- `errorCode`
- `exceptionType`

## 4. 访问日志模板

### 4.1 适用场景

适用于：

- HTTP 请求进入
- HTTP 请求完成
- 关键 RPC 或外部调用入口

### 4.2 推荐字段

- `traceId`
- `module`
- `action`
- `method`
- `path`
- `status`
- `durationMs`
- `clientIp`

### 4.3 模板示例

```text
http_access traceId={traceId} module={module} action={action} method={method} path={path} status={status} durationMs={durationMs} clientIp={clientIp}
```

## 10. traceId 使用规范

要求：

- 每个请求必须有唯一 `traceId`
- 上游透传优先复用
- 下游日志统一带 `traceId`
- 响应头回写 `traceId`

作用：

- 串联 Controller、Service、DAO、异常和测试日志
- 支撑自动 bug 修复时的单次请求回放分析

## 11. 敏感信息规范

禁止直接写入日志：

- 明文密码
- token 原文
- access key / secret key
- 大段原始个人隐私信息

允许写摘要或脱敏值，例如：

- `tokenPrefix`
- `operatorId`
- `resourceId`

## 12. 自动 bug 修复友好要求

为支持后续自动 bug 修复，日志应尽量满足：

- 同一类失败拥有稳定 `errorCode`
- 关键业务动作拥有稳定 `action`
- 关键模块拥有稳定 `module`
- 日志字段顺序和语义尽量一致

这样后续才能把：

- 日志
- 测试
- 缺陷
- 修复记录

做稳定关联。

## 13. 推荐字段字典

建议统一使用：

- `module`：模块名
- `action`：业务动作
- `status`：成功/失败/进行中
- `resourceId`：业务主键或资源标识
- `operator`：操作人或调用方
- `durationMs`：耗时
- `errorCode`：稳定错误码
- `exceptionType`：异常类型
- `summary`：可读摘要

## 14. 执行要求

以后新增模块或重构模块时：

1. 访问日志、业务日志、系统错误日志必须按本文档统一。
2. 不得在正式业务代码中继续扩散 `System.out.println`。
3. 不得输出无 `traceId` 的核心请求链路日志。
4. 新增重要业务动作时，应同时补日志模板与日志字段说明。
