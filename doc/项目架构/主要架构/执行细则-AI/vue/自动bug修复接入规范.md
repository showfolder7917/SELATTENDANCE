# SELSP Vue自动bug修复接入规范

## 1. 文档定位

本文档用于规定 `SELATTENDANCE/SELVUE` 后续接入自动 bug 修复能力时，Vue 前端工程必须满足的基础条件和实施规范。

自动修复链路中的页面定位、工作台分层和共享组件判断，必须优先基于：

- `/Users/showfolder/Documents/workSpace/SELF/SELATTENDANCE/SELVUE/src/projects/attendance`
- 不再以 `SELTEMPLATE` 的旧前端模板目录推断当前项目真实结构

## 2. 接入目标

接入自动 bug 修复后，至少要支持：

- 自动定位问题页面和问题层
- 自动关联页面证据、日志和测试
- 自动构造最小修复范围
- 自动执行页面回归验证

## 3. 工程前置条件

必须具备：

1. 页面边界清晰
2. 组件边界清晰
3. composable 与 service 分层清晰
4. 可执行构建验证
5. 可执行页面验证
6. 文档可检索
7. 启动器与联调桥接可执行

## 4. 测试接入要求

- 至少存在可执行构建测试
- 视觉问题必须能留下真实页面证据
- 修复后必须补目标回归验证
- 相邻交互链路至少做一轮最小回归
- 若问题发生在启动脚本、端口接管、代理桥接或本地联调链路，必须补脚本级可执行验证，不能只重跑页面截图。

## 5. 缺陷定位输入要求

自动修复入口应优先接受：

- 失败页面 URL
- 失败截图
- 失败交互动作
- 失败请求
- 失败控制台日志
- 失败启动脚本
- 失败端口或代理日志

## 6. 自动修复执行边界

自动修复默认只应修改：

- 明确命中的页面
- 明确命中的组件
- 明确命中的 composable / service
- 与当前缺陷直接相关的主题或样式文件
- 明确命中的启动脚本、开发代理配置或联调桥接文件

若问题命中独立主题包或共享样式层，应优先继续细分到主题组件层，而不是只落到笼统的 `components.css`：

- `theme_tokens`
- `theme_buttons`
- `theme_forms`
- `theme_overlays`
- `theme_preview_entry`

若主题包采用聚合入口结构，还应先判断问题属于：

- 聚合入口引用问题
- 分层组件文件内容问题
- preview/demo 页面错误引用问题

避免把“按钮层问题”“输入层问题”“浮层问题”都混成一次大范围主题改写。

若问题属于启动链缺口，应优先明确缺口类型，而不是笼统写“补能力”：

- `launcher_script`
- `backend_launcher_script`
- `fullstack_launcher_orchestrator`
- `dev_proxy_bridge`
- `page_output_verifier`

## 7. 验证闭环

自动修复完成后至少形成三类验证：

1. 复现验证
2. 修复验证
3. 相邻回归验证

若问题命中启动链，还必须额外形成：

4. 启动器生命周期验证
5. 端口回收验证
6. 远端联调模式验证

## 8. 执行要求

以后凡是声称“已接入自动 bug 修复能力”的 Vue 模块，至少应满足：

1. 有清晰目录结构
2. 有可执行测试或页面验证
3. 有页面级或模块级文档
4. 有稳定的状态和服务边界
