# SELSP Vue 架构

## 1. 文档定位

本文档只描述当前项目前端工程 `SELVUE` 的正式 Vue 架构。

唯一主参照：

- `SELVUE/src/projects/attendance`

跟随参照：

- `SELVUE/src/projects/uniauth`

## 2. 真实目录基线

当前前端正式基线以 `attendance` 为主参照。

```text
SELVUE/
├─ src/
│  ├─ App.vue
│  ├─ main.js
│  ├─ projects/
│  │  ├─ attendance/
│  │  └─ uniauth/
│  └─ shared/
└─ ...
```

每个正式前端工程都必须按 `attendance` 当前结构组织：

```text
src/projects/{project}/
├─ components/
├─ composables/
│  └─ workbench/
├─ constants/
├─ services/
├─ testing/
├─ theme-presets/
├─ views/
├─ style.css
└─ index.js
```

禁止：

- 单个大 view 既写布局又写状态又写请求
- 旧 panel 聚合组件长期存在
- constants 和接口函数继续散在页面里
- 一个新工程另起一套目录命名
- 真实已经存在的 `testing`、`theme-presets` 目录继续游离在规范之外

## 3. 命名规则

命名统一参照 `attendance`：

- 页面根视图：`{Project}WorkbenchView.vue`
- 工程入口：`index.js`
- 状态总入口：`use{Project}Workbench.js`
- 真正实现下沉到 `composables/workbench/index.js`
- 区块组件：`TenantSection.vue`、`RuleSection.vue`、`MonthlySection.vue`
- 服务文件：`tenantApi.js`、`ruleApi.js`、`monthlyApi.js`
- 常量文件：`i18nMessages.js`、`themeOptions.js`、`workbenchSections.js`

禁止：

- 同一工程内同时存在 `SectionPanel` 与 `Section`
- `messages.js`、`copy.js`、`strings.js` 混着来
- service 命名一半按 `Api`、一半按 `Service`

说明：

- 导航类组件不强制命名为 `Section`
- 但业务区块组件必须统一到 `Section` 口径

## 4. Shared 引用规则

凡是正式工作台页，优先复用已落地 shared 能力：

- `SharedWorkbenchHeader`
- `ThreePaneWorkbenchLayout`
- `SharedMetricCards`
- `LanguageSwitch`
- `ThemeSwitch`
- 共享 request 包装
- 共享 auth session

禁止：

- 新工程自己再写第二套 workbench header
- 新工程自己再写第二套三分栏布局
- 新工程自己再写第二套主题切换器
- 新工程只做“看起来像”但不用 shared 组件

## 5. 布局规则

正式工作台统一节奏：

1. hero
2. message / toast
3. left nav
4. shared header
5. main section
6. side panel

也就是说：

- 登录前是精简态
- 登录后必须进入正式 workbench 壳
- 搜索、指标卡、标题、说明要从表格区剥离
- 不允许再把“标题 + 搜索 + 指标卡 + 表格”全部堆进一个自定义 panel

## 6. 国际化规则

本项目明确是中日双语。

前端正式规则：

- 工程内统一存在 `constants/i18nMessages.js`
- 文案 key 必须稳定
- `localeOptions` 统一结构
- 中文默认 `zh-CN`
- 日文默认 `ja-JP`
- 页面、按钮、表头、提示、状态、模块标题都必须进字典

禁止：

- 在组件模板里继续硬编码中文或日文
- 新工程自己维护第二套 locale 结构
- 部分 key 放 constants，部分 key 写死在 view

## 7. 主题与视觉规则

当前真实主参照不是 `SELTEMPLATE` 主题演示页，而是：

- `SELVUE/src/projects/attendance/style.css`
- `SELVUE/src/projects/attendance/theme-presets/*`

正式规则：

- 新工程优先复用 attendance 已稳定主题预设
- 工程自己的 `style.css` 只做本工程局部布局和差异补充
- 颜色、阴影、面板质感、按钮态优先跟随宿主

禁止：

- 新工程重新自创一套主题 token
- 新工程只做颜色接近但布局节奏不同
- 新工程同时保留旧浅色表单页和新工作台页两套壳

## 8. 启动与联调规则

正式要求：

- 前端必须支持本地单前端启动
- 全套必须支持一键启动
- 前端开发态默认走相对路径 + vite proxy
- 代理目标、后端端口和失败日志必须明确

当前真实问题也必须写入规范：

- 页面真实验证时，如果前端能打开但 `/api/*` 代理到后端端口失败，不能把任务写成“页面已联调完成”
- 必须明确区分：
  - 布局验证通过
  - 后端联调失败

## 9. 一次做成自检清单

新增正式工程或正式区块前，提交前至少自检：

- 是否先参照 `attendance` 当前项目结构
- 是否已按 `components/composables/constants/services/views` 分层
- 是否已接 shared header / shared layout / theme / i18n
- 是否仍残留旧 panel、旧 messages、旧聚合 service
- 是否页面结构已从表格区剥离标题和搜索
- 是否中日双语已全部接字典
- 是否把 `testing`、`theme-presets` 一起纳入工程正式目录

## 10. 当前结论

前端架构执行原则：

- **先看 `attendance`**
- **再让 `uniauth` 跟同一套工程规则**
- **最后才看模板**

如果真实项目和模板冲突：

- **优先按真实项目规范修模板**
- **禁止让真实项目回退去兼容旧模板**
