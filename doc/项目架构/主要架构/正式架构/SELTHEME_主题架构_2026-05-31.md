# SELTHEME 主题工程架构标准

## 1. 文档定位

本文档用于约束独立主题工程的通用架构标准。

当前主题工程唯一正式依赖参照是：

- `/Users/showfolder/Documents/workSpace/SELF/SELTEMPLATE/SELTHEME`
- `SELATTENDANCE` 中的业务前端工程只能消费该主题工程，不应反向把业务结构当成主题结构基线

目标不是描述某一套具体主题效果，而是统一以下内容：

- 主题工程的目录边界
- 主题集合层与单主题包层的关系
- tokens、components、assets、preview 的标准落点
- 主题验证与复用方式
- 面向自动修复的演进边界

## 2. 架构目标

- 让同一个主题工程可以持续沉淀多套主题，而不是只承载一套散落样式。
- 让每套主题都具备独立的变量、组件样式、资产和预览入口。
- 让业务工程能稳定消费主题结果，而不需要反向猜测主题文件位置。
- 让目录结构足够稳定，以便后续自动修复和自动验证直接命中。

## 3. 技术基线

- CSS Variables
- 独立组件样式文件
- 独立 SVG 或位图主题资产
- 独立 preview 预览入口
- 可通过本地静态服务直接验证

## 4. 目录标准

推荐目录结构如下：

```text
SELTHEME/
├─ README.md
├─ 打开<theme-name>主题Demo.command
├─ doc/
│  └─ 主题说明文档
└─ themes/
   ├─ liquid-glass/
   │  ├─ README.md
   │  ├─ tokens.css
   │  ├─ components.css
   │  ├─ components/
   │  │  ├─ buttons.css
   │  │  ├─ forms.css
   │  │  ├─ tabs.css
   │  │  ├─ tables.css
   │  │  ├─ trees.css
   │  │  └─ overlays.css
   │  ├─ scripts/
   │  │  ├─ index.js
   │  │  ├─ buttons.js
   │  │  ├─ forms.js
   │  │  ├─ tabs.js
   │  │  ├─ tables.js
   │  │  ├─ trees.js
   │  │  └─ overlays.js
   │  ├─ assets/
   │  └─ preview/
   │     ├─ index.html
   │     ├─ demo.html
   │     ├─ fragments/
   │     ├─ scripts/
   │     └─ styles/
   └─ other-theme/
```

目录约束：

- `SELTHEME` 根目录只保留主题集合入口、总说明、文档和必要的 demo 打开脚本。
- `themes/` 只承载单主题包目录，不直接平铺样式或图片。
- `themes/<theme-name>/` 是唯一合法的单主题包根目录。
- 每个主题包至少包含 `tokens.css`、`components.css`、`assets/`、`preview/`。
- `doc/` 只承载主题工程说明，不承载具体业务页面文档。

## 5. 分层标准

### 5.1 主题集合层

职责：

- 承载多套主题的统一入口
- 给业务工程提供可检索的主题目录结构
- 承载工程级说明文档

约束：

- 不直接定义具体主题 token
- 不直接平铺预览页和图片资产

### 5.2 单主题包层

职责：

- 承载某一套主题的完整实现
- 提供完整变量、组件样式、资产和预览页

约束：

- 一个主题包只负责一套主题语言
- 不在同一个主题包里混入多个风格分支

### 5.3 Token 层

职责：

- 定义颜色、模糊、圆角、阴影、透明度等全局变量

约束：

- `tokens.css` 只定义变量，不写大段页面结构样式

### 5.4 Component 层

职责：

- 定义卡片、按钮、输入框、标签、开关等主题组件样式

约束：

- `components.css` 应优先消费 `tokens.css` 中的变量
- `components.css` 应作为聚合入口，继续统一引入各组件子层
- 若主题已经进入复用阶段，应继续拆分 `components/buttons.css`、`components/forms.css`、`components/tabs.css`、`components/tables.css`、`components/trees.css`、`components/overlays.css`
- 不把临时页面布局硬编码成组件样式标准
- `buttons.css` 负责按钮、胶囊、圆形图标按钮和操作触发器
- `forms.css` 负责输入框、搜索框、复选框、开关、建议面板和筛选控件
- `tabs.css` 负责 tabs、segmented tabs 和分段切换控件
- `tables.css` 负责表格容器、表头、行高亮和列表型数据展示
- `trees.css` 负责树导航、层级缩进、节点切换和树节点状态
- `overlays.css` 负责 tip、右键菜单、提示气泡、统计卡、资料卡、模态卡、toast 和展示浮层

### 5.4.1 Theme Script 层

职责：

- 为主题包提供和组件子层一一对应的元数据与最小行为脚本
- 让 preview/demo 和业务消费端读取统一的主题层定义，而不是再手写一套目录说明

约束：

- `scripts/index.js` 应作为主题脚本聚合入口
- `scripts/buttons.js`、`scripts/forms.js`、`scripts/tabs.js`、`scripts/tables.js`、`scripts/trees.js`、`scripts/overlays.js` 应和组件子层保持同名对应
- 脚本层优先承载主题层元数据、样例清单、目录映射和最小互动行为
- 不允许 preview 目录自己维护一套脱离主题脚本层的平行层级定义

### 5.5 Asset 层

职责：

- 承载光效、雾化、球体、纹理、插图等视觉资产

约束：

- 资产应按主题包本地相对引用组织
- 禁止主题包引用其他主题包内部私有资产

### 5.6 Preview 层

职责：

- 给主题包提供独立的可视化验证入口
- 承接主题展示页、互动实验页和 demo 壳层

约束：

- `preview/index.html` 应只依赖本主题包内的样式和资产
- 必须支持静态服务直接打开验证
- 若 demo 已进入“可互动、可评估”阶段，不应长期把所有结构、展示区和交互逻辑堆叠在单个 html 中
- 推荐拆为 `demo.html` 壳页、`fragments/` 片段、`scripts/` 交互脚本、`styles/` 预览专属样式
- `index.html` 可作为稳定入口，但应跳转或委派到正式的互动 demo 壳页
- 若 preview 承担正式样例页职责，应至少提供分组导航、样例展示区、互动状态和可见反馈区
- 若 preview 左侧目录或样例导航来自主题层定义，应优先读取 `scripts/index.js` 聚合出来的正式元数据
- 若 preview 或业务页中的主题工作区采用“左侧目录 + 右侧样例区”结构，右侧样例区必须显式禁止被左侧目录高度拉伸
- 主题工作区中的右侧样例区应优先设置 `align-self:start / align-content:start / min-width:0`，避免单个样例层被目录高度撑出大面积空白
- 若左侧主题目录、分组导航或状态侧栏的内容可能超过当前视口高度，该目录区必须提供独立纵向滚动，不得要求用户只能通过整页滚动才能访问末尾分组
- 若运行环境可能隐藏原生 overlay 滚动条，主题工作区应补充固定轨道、滑块或等价的可见滚动提示，不能把“可滚动”完全押注在系统滚动条自动显隐上
- 若主题工作区包含 `Live State`、交互反馈或运行说明，这类反馈块应优先放在目录上方或主操作区附近，不得长期沉到底部让用户必须滚动后才能看到变化
- 若主题工作区已经具备目录、样例头部和主操作区，介绍性横幅不应继续独占整行首屏高度；说明应压缩到局部说明卡，或直接删掉，把首屏空间让给可操作内容
- `Reset demo`、样例数量或层级切换这类仍然需要保留的动作，应并入内容区头部，而不是为了保留动作继续维持整块 hero 横幅
- 若页面级顶部说明区仍需保留，应优先提供折叠能力，并允许主题页默认以收起态进入，把首屏空间优先让给表格、控件和样例内容
- 当某一主题层只有一个样例卡时，样例网格必须自动退化为单卡布局，并限制单卡最大宽度，避免继续保留空白列
- 主题工作区的顶部筛选胶囊、层级标签和 reset 操作应优先横向换行，不应默认堆成竖列去拉高首屏 hero
- 若主题工作区包含 `Live State`、互动反馈区或说明面板，面板高度必须预留稳定空间，不得因为文案长度切换而反复增减页面总高度
- 当互动反馈区会随点击、切换或输入实时改写文案时，应优先同时设置稳定最小高度和 `overflow-anchor:none`，避免浏览器滚动锚点把页面视口上下推拉

### 5.7 Preview 启动层

职责：

- 为需要 `fetch fragments`、`module script` 或本地静态服务的主题 demo 提供稳定打开方式

约束：

- 若 preview/demo 不能直接通过 `file://` 正常打开，应提供根目录 `.command` 启动脚本或等价启动器
- 启动脚本应固定端口、打印访问地址并接管本轮静态服务生命周期
- 启动脚本退出时必须回收端口和子进程
- README 必须写明启动脚本名、访问地址和适用场景

## 6. 复用标准

- 业务工程应优先消费主题包导出的 token 和组件样式，而不是复制粘贴主题定义。
- 若业务工程需要裁剪主题资产，应保留原主题包不变，在业务工程内做消费级同步。
- 若形成一套新风格，应新增主题包，不应直接改坏已有主题包。

## 7. 测试标准

- 每次目录重构后必须检查预览入口和相对引用。
- 每次主题样式调整后必须做真实预览验证。
- 主题效果问题不能只靠静态阅读 CSS 判断完成。
- 主题包应至少保留一份可复现截图或等价证据。
- 若 demo 已进入互动阶段，必须补浏览器级点击、输入、切换或浮层验证，而不只是首屏截图。
- 对 `buttons/forms/overlays` 这类分层主题样例，至少验证每层一个核心控件能实际反馈状态变化。
- 对 `tables` 层，除了基础数据表，还应允许沉淀带摘要、批量动作或阶段字段的 richer table demo。
- 对 `overlays` 层，除了长说明气泡，还应允许沉淀 tip 和右键菜单这类轻浮层或快捷菜单样例。
- 对 `tabs/tables/trees` 这类新增主题层，至少验证目录可见、样例可见和一个核心交互可用。
- 对“左侧目录 + 右侧样例区”的主题工作区，至少验证右侧样例区不会因左侧目录更高而出现异常纵向拉伸。
- 对带左侧目录的主题工作区，至少验证目录区在窄屏或低视口高度下会出现独立滚动条，并能滚到最后一项和状态面板。
- 对带左侧目录的主题工作区，若运行环境默认隐藏原生滚动条，还必须验证固定轨道或等价滚动提示在截图中肉眼可见，并且滚动后位置会变化。
- 对带实时反馈块的主题工作区，至少验证点击主操作后无需滚到页面下方即可看到反馈内容变化。
- 对删除或收紧顶部说明横幅的主题页，至少验证首屏高度下降，且目录、样例标题和主操作控件依然处于可见范围。
- 对改为可折叠的顶部说明区，至少验证默认收起态与展开态都可用，并确认收起后下方内容区出现可见上移。
- 对只有单个样例卡的主题层，至少验证样例卡宽度受控、标题与卡片之间无异常大空白、网格没有残留空列。
- 对带有反馈面板的主题工作区，至少验证不同按钮、单选或页签切换后 `scrollY` 与页面总高度保持稳定，不出现视口上下跳动。
- 若发生主题前缀或目录命名统一替换，还必须补残留检索验证，确认旧前缀文本已清零。

## 8. 自动修复接入目标

- 主题集合层结构清晰
- 单主题包边界清晰
- 资产与样式引用稳定
- preview 可真实回放
- 文档和目录关系稳定
