SELATTENDANCE Uniauth 当前权限架构说明

本说明基于当前 SELATTENDANCE / SELSP + SELVUE 实现，整理统一权限中心 uniauth 的运行时权限主链路、授权聚合方式和 Module 在系统中的真实职责边界。

生成日期：2026-06-04 范围：SELVUE + SELSP 主题：Tenant / User / Role / Menu / Permission / DataScope / Module

1. 一句话结论

当前系统采用基于 RBAC 的权限模型。权限主链路是 Tenant -> User -> UserRole -> Role，角色统一聚合并下发 menuCodes、permissionCodes、dataScopes 三类运行时授权信息；Module 负责业务域和工程主数据登记，是 Menu、Permission、DataScope 的归属维度，但不直接参与运行时放行判断。

Tenant -> User 用户主表 ua_user 带有 tenant_id，说明一个租户下可以有多个用户，而用户当前归属一个租户。
User -> UserRole -> Role 用户与角色通过关系表形成多对多绑定。角色不是只承接显示名称，而是系统真正的授权聚合单元。
Role -> menuCodes / permissionCodes / dataScopes 当前实现里，角色同时下发页面权限、操作权限和数据范围表达，运行时统一进入当前用户上下文。

3. 三类授权的职责划分

页面权限

menuCodes

负责控制页面与工程入口可见性。前端宿主会把当前登录态中的 menuCodes 与各工程声明的 requiredMenuCodes 对比，决定项目切换器里是否显示对应工程。

操作权限

permissionCodes

负责控制接口和按钮级操作。后端 controller/service 通过权限守卫按权限码阻断越权保存、维护和读取动作。

数据权限

dataScopes

负责表达用户可访问的数据范围。当前口径主要服务于 attendance 宿主，把租户级、部门级或本人级过滤条件带到后续业务查询。

4. currentUser 运行时上下文

登录成功后，系统不会让前端再去分别查角色、菜单、权限和数据范围，而是把当前用户的有效授权关系聚合成一个统一上下文，供前后端共同消费。

字段 作用 主要消费方
tenantId / tenantCode 表达当前用户所在租户，作为业务系统默认数据隔离边界。 权限中心头部、attendance 宿主、后端查询过滤
menuCodes 表达当前用户可见的菜单与工程入口。 SELVUE 宿主项目切换、菜单显隐
permissionCodes 表达当前用户允许执行的接口和按钮动作。 后端权限守卫、前端按钮显隐
dataScopes 表达当前用户可访问的数据范围集合。 attendance 侧业务查询、后续 SQL / 条件拼装

5. Module 的真实职责

主数据

模块登记

Module 用来定义系统里有哪些业务域或工程，例如 attendance、uniauth、seltheme。

入口信息

工程入口元数据

模块表会保存 entryProject、routeKey、ownerSystem 等信息，方便宿主和管理台识别模块属于哪个前端入口、默认落点在哪。

归属维度

namespace

moduleCode 会出现在 Menu、Permission、DataScope 等定义里，作为这些授权对象的归属维度和命名空间。

边界说明

不直接参与放行

当前模块服务只维护模块主表，不会在保存模块时隐式创建菜单和权限，也不会直接决定某个请求是否放行。真正参与运行时判断的是 menuCodes、permissionCodes、dataScopes。

6. 当前实现里的典型运行路径

步骤 1：用户登录 登录链路先按账号读取用户主数据和租户状态，再组装当前用户上下文。
步骤 2：聚合授权 系统按用户主键读取该用户绑定角色所对应的 permissionCodes、menuCodes 和 dataScopes。
步骤 3：签发 currentUser JWT 和当前用户快照中都会带上租户、菜单、权限和数据范围，避免前端初始化时重复查多张关系表。
步骤 4：宿主消费 menuCodes 宿主根据工程声明的 requiredMenuCodes 和当前用户的 menuCodes 决定显示哪些工程入口。
步骤 5：后端消费 permissionCodes / dataScopes 后端接口用权限码阻断越权操作，业务系统后续再根据数据范围拼装租户级或更细粒度的过滤条件。

7. 现状边界与注意事项

  • 当前系统已经形成完整的 Tenant -> User -> Role 授权链和 currentUser 聚合输出。
  • menuCodes 已真实参与前端工程显隐，不只是设计概念。
  • permissionCodes 已真实参与后端保存与维护接口的权限校验。
  • dataScopes 当前主要面向 attendance 宿主的数据过滤场景，后续如果扩展更多业务系统，需要继续把消费口径补齐到各模块查询链。
  • Module 当前是主数据和归属维度，不应误写成直接参与运行时访问控制的对象。

8. 结论

因此，当前 SELATTENDANCE 的 uniauth 权限架构可以概括为：以租户为隔离边界、以用户为登录主体、以角色为授权聚合中心、以 menuCodes / permissionCodes / dataScopes 作为运行时下发结果；Module 负责定义业务域和归属命名空间，但不直接参与运行时放行判断。

文档定位：当前实现说明。若后续把模块授权、更多业务系统接入或更细粒度数据范围消费补齐，应另行更新此页。
