SELATTENDANCE Uniauth 用户模块架构说明

本说明聚焦统一权限中心中“用户”模块的实现方式，覆盖前端区块装配、会话与请求链、后端控制器/服务/DAO、MyBatis SQL 以及新增/编辑用户时的完整数据流。

生成日期：2026-06-03 范围：SELVUE + SELSP 模块：Uniauth / User

1. 一句话结论

“用户”模块不是独立页面，而是 UniauthWorkbenchView 五个管理域中的一个区块。前端通过 bootstrap 聚合接口一次性拿到用户列表，通过单独的用户保存接口维护账号资料与角色绑定；后端则把用户主表 ua_user 与角色关系表 ua_user_role 的维护收口在 UniauthUserServiceImpl 中处理。

2. 前端实现分层

入口视图

UniauthWorkbenchView.vue

统一权限中心总页面。它负责三栏工作台装配，并在当前激活区块为 user 时，把用户列表区和用户表单区挂到中栏与右栏。

路径：SELVUE/src/projects/uniauth/views/UniauthWorkbenchView.vue

区块切换

UniauthSectionNav.vue

左侧导航只负责切换区块，不负责请求。用户模块的左侧显示文字来自 navUser 和 sectionUserHint 国际化文案。

路径：SELVUE/src/projects/uniauth/components/UniauthSectionNav.vue

状态编排

useUniauthWorkbench

这是用户模块真正的前端业务中枢。它维护 userRows、userForm、submitUser()、editUser() 和整页 bootstrap 回刷。

路径：SELVUE/src/projects/uniauth/composables/workbench/index.js

展示组件

UserSection.vue

只负责渲染，不直接发请求。pane="table" 时显示用户表格，pane="form" 时显示账号编辑表单。

路径：SELVUE/src/projects/uniauth/components/UserSection.vue

3. 用户区块前端数据结构

状态名 位置 作用
userRows useUniauthWorkbench() 承接 bootstrap 返回的用户列表，供中栏表格渲染。
userForm useUniauthWorkbench() 承接当前编辑中的账号主资料与角色绑定表达。
SUMMARY_DEFAULTS.userCount useUniauthWorkbench() 驱动左侧导航 badge 和摘要卡中的用户数量。
editUser(row) useUniauthWorkbench() 点击用户表格行后，把当前行字段回填到右侧表单。
submitUser() useUniauthWorkbench() 把表单归一化后调用保存接口，成功后重新刷新整页 workbench。

4. 前端请求链

4.1 首屏读取用户列表 reloadWorkbench() 调用 fetchUniauthWorkbench()，请求 GET /api/uniauth/bootstrap，后端一次性返回 users、summary.userCount 和 currentUser。
4.2 表格点击进入编辑 UserSection.vue 点击行后触发 edit 事件，交给 editUser(row) 回填到 userForm。
4.3 保存用户 submitUser() 把 roleIdsText 通过 parseNumberList() 变成 roleIds 数组，然后调用 saveUser()，请求 POST /api/uniauth/users。
4.4 保存成功后的回刷 保存成功后不直接手工改局部列表，而是再次执行 reloadWorkbench({ silent: true })，让用户列表、摘要卡、当前用户快照重新走同一口径。 
SELVUE
UserSection.vue
  -> emit('submit')
  -> useUniauthWorkbench.submitUser()
  -> saveUser(payload)
  -> requestJson('/api/uniauth/users', { method: 'POST' })
  -> 后端返回成功
  -> reloadWorkbench()
  -> requestJson('/api/uniauth/bootstrap')
  -> userRows / summary / currentUser 全量刷新

5. 会话与鉴权链

前端会话

authSession.js

登录态保存在浏览器 localStorage 的 selattendance.uniauth.session。readAccessToken() 专门提供 token 给请求层使用。

请求层

request.js

requestJson() 每次发请求前都会读取最新 token，并自动加上 Authorization: Bearer ... 请求头。

后端拦截

UniauthWebMvcConfig

拦截 /api/uniauth/**，解析 Bearer Token，并把当前用户装进 UniauthCurrentUserContext。

强制登录

requireUser + PermissionGuard

控制器通过 UniauthCurrentUserContext.requireUser() 要求当前请求必须已有登录用户；服务层再用 UniauthPermissionGuard.ensurePermission(...) 校验 uniauth.user.write 等权限码。

6. 后端实现分层

层 文件 职责
读取入口 bootstrap/controller/UniauthBootstrapController.java 提供 GET /api/uniauth/bootstrap，一次性返回用户列表和其他管理域列表。
读取服务 bootstrap/service/impl/UniauthBootstrapServiceImpl.java 校验 uniauth.bootstrap.read 后，调用 DAO 聚合读取 users、summary 和 currentUser。
写入入口 user/controller/UniauthUserController.java 提供 POST /api/uniauth/users，统一承接新增和更新。
写入服务 user/service/impl/UniauthUserServiceImpl.java 校验权限、补默认值、可选重算密码摘要、重建用户角色关系、写审计日志。
DAO 接口 user/dao/UniauthUserDao.java 定义用户主表插入/更新、按登录名和主键查询、删除角色关系、插入用户角色关系。
SQL 映射 user/dao/mapper/UniauthUserDao.xml 真正执行 ua_user 和 ua_user_role 的 SQL。

7. 数据库读写口径

列表读取

bootstrap user list

UniauthBootstrapDao.xml 里的 selectUserList 从 ua_user u 左连接 ua_tenant t，把 tenant_code 一起带回前端表格。

SELECT u.id, u.tenant_id, t.tenant_code, u.login_name, u.display_name,
u.display_name_kana, u.locale, u.email, u.phone, u.user_status, u.locked_flag
FROM ua_user u
LEFT JOIN ua_tenant t ON t.id = u.tenant_id
ORDER BY u.id
主表写入

ua_user

新增时写入 tenant_id、login_name、password_hash、display_name、locale、user_status 等字段；更新时支持“有密码则更新密码、无密码则保留旧密码”。

关系写入

ua_user_role

每次保存用户都先删掉旧关系，再逐条插入新的 role_id 集合，因此前端提交的角色列表就是用户最终绑定结果。

审计日志

ua_audit_log

保存成功后调用公共审计写入器，记录 save-user 动作，便于追踪是谁改了哪个账号。

8. 用户保存完整时序

浏览器右栏表单输入
  -> submitUser()
  -> saveUser(payload)
  -> POST /api/uniauth/users
  -> UniauthUserController.saveUser()
  -> UniauthCurrentUserContext.requireUser()
  -> UniauthUserServiceImpl.saveUser()
       -> ensurePermission("uniauth.user.write")
       -> requireText(loginName)
       -> requireText(displayName)
       -> locale 默认 zh-CN
       -> userStatus 默认 ACTIVE
       -> 有 password 时生成 passwordHash
       -> insertUser 或 updateUser
       -> deleteUserRoles(userId)
       -> insertUserRole(userId, roleId...)
       -> selectUserById(userId)
       -> write audit log
  -> CommonResponse.success(userRow)
  -> 前端 reloadWorkbench()
  -> GET /api/uniauth/bootstrap
  -> 用户表格与摘要刷新

9. 关键实现特点

  • 用户模块目前没有单独的“查询用户接口”，而是复用 bootstrap 聚合接口统一读取。
  • 用户编辑区不是弹窗，而是工作台右栏固定表单，点击中栏表格行后回填编辑。
  • 角色绑定不是前端多选组件，而是文本形式的 roleIdsText，提交前再转成数字数组。
  • 密码更新采用“可选覆盖”模式，更新资料时不传密码就不会修改旧密码摘要。
  • 权限中心是独立数据源，Uniauth DAO 通过单独的 uniauthSqlSessionFactory 访问权限库，而不是 attendance 主库。
