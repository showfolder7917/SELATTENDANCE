# 日本通用勤怠排班系统 第一阶段测试数据

> 用途：用于第一阶段开发、自测、联调、初始化向导展示、员工导入导出和推荐班次验证。

## 0. 使用范围

本测试数据只覆盖第一阶段：

- 公司 / 教室基础信息
- 事业所
- 部门
- 员工
- 员工默认勤怠规则
- 员工外部打卡映射
- 班次模板

不覆盖：

- 排班数据
- 打卡原始数据
- 日次勤怠结果
- 月次汇总结果
- 审批数据

## 1. 测试数据设计目标

- 目标 1：验证初始化向导进度计算。
- 目标 2：验证事业所、部门、员工、班次模板基础 CRUD。
- 目标 3：验证员工外部打卡 ID 绑定提醒。
- 目标 4：验证推荐班次模板一键生成。
- 目标 5：验证员工导入导出主路径。
- 目标 6：验证中日双语页面在有数据和无数据时都能正常展示。

## 6. 初始化向导状态测试场景

## 6.1 场景 A：只有公司信息

数据准备：

- 仅有 `tenant`
- 没有 `workplace`
- 没有 `employee`
- 没有 `shift_template`

预期：

- 公司信息：已完成
- 事业所：需要处理
- 员工：需要处理
- 班次模板：需要处理
- 推荐下一步：新增事业所

## 6.2 场景 B：基础资料已完成但无外部映射

数据准备：

- 有 `tenant`
- 有 `workplace`
- 有 `department`
- 有 `employee`
- 有 `shift_template`
- 没有 `employee_external_mapping`

预期：

- 初始化向导主体步骤显示已完成。
- 员工管理页中显示未绑定外部打卡 ID 的黄色提醒。
- 推荐下一步：绑定外部打卡 ID。

## 6.3 场景 C：第一阶段全部完成

数据准备：

- 使用本文件中的全部主数据。

预期：

- 公司 / 教室信息：已完成
- 事业所：已完成
- 员工：已完成
- 班次模板：已完成
- 默认勤怠规则：已完成
- 推荐下一步：进入排班阶段

## 7. 推荐班次模板生成测试

## 7.1 空模板场景

前置条件：

- `shift_template` 表为空。

执行：

- 调用推荐班次模板生成接口。

预期：

- 新增 6 条模板。
- 返回新增数量 `6`。
- 页面立即可见早班、晚班、夜班、半日、休息、有休。

## 7.2 已有部分模板场景

前置条件：

- 已存在 `EARLY`、`LATE`。

执行：

- 调用推荐班次模板生成接口。

预期：

- 不重复生成已有编码模板。
- 返回：
  - 新增数量
  - 跳过数量
- 页面能看到完整推荐模板集合。

## 8. 双语测试文案数据

建议第一阶段至少校验以下双语字段：

```text
员工管理 / 従業員管理
事业所 / 事業所
部门 / 部門
班次模板 / シフトテンプレート
未绑定打卡ID / 打刻ID未連携
一键生成推荐班次 / 推奨シフトを一括生成
新增员工 / 従業員を追加
批量导入 / 一括取込
```

## 9. 最小联调组合建议

建议最少准备以下三组数据包：

- 数据包 1：空系统包
  - 只有默认租户
  - 用于验证初始化向导空状态
- 数据包 2：基础资料半完成包
  - 有租户、事业所、部门
  - 无员工、无班次
  - 用于验证推荐下一步
- 数据包 3：第一阶段完成包
  - 使用本文件完整数据
  - 用于验证第一阶段完成态与导入导出主路径
