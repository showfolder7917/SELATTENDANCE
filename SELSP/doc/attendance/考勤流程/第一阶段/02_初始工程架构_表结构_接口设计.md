# 日本通用勤怠排班系统 第一阶段初始工程架构、表结构与接口设计

> 范围说明：本文件只覆盖第一阶段需要直接落地的工程骨架、数据库表和接口设计。

## 0. 适用范围

第一阶段覆盖范围：

- `tenant`
- `workplace`
- `department`
- `employee`
- `employee_work_rule`
- `employee_external_mapping`
- `shift_template`
- 初始化向导汇总能力

不在第一阶段实现的范围：

- `shift_schedule`
- `punch_raw_log`
- `attendance_daily`
- `attendance_monthly`
- `approval_request`
- `leave_balance`
- 外部打卡正式接入

## 2. 第一阶段表结构设计

## 2.1 tenant

用途：

- 承载公司 / 教室 / 机构的顶层信息。
- 第一阶段的“公司信息设置”页面直接对应本表。

```sql
CREATE TABLE tenant (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_code VARCHAR(50) NOT NULL UNIQUE COMMENT '租户编码',
    tenant_name VARCHAR(200) NOT NULL COMMENT '租户名称',
    status VARCHAR(30) NOT NULL DEFAULT 'ACTIVE' COMMENT '状态',
    contact_name VARCHAR(100),
    contact_phone VARCHAR(50),
    contact_email VARCHAR(100),
    timezone VARCHAR(50) DEFAULT 'Asia/Tokyo',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

第一阶段落地说明：

- 第一阶段只需要单租户使用方式，但表结构从一开始保留多租户字段。
- 页面上建议只允许维护当前租户，不做复杂租户列表运营。

## 2.2 workplace

用途：

- 承载事业所、门店、教室、办公地点。
- 员工归属和后续排班场景依赖本表。

```sql
CREATE TABLE workplace (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    workplace_code VARCHAR(50) NOT NULL,
    workplace_name VARCHAR(200) NOT NULL,
    address VARCHAR(500),
    phone VARCHAR(50),
    status VARCHAR(30) DEFAULT 'ACTIVE',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_tenant_workplace_code (tenant_id, workplace_code)
);
```

## 2.3 department

用途：

- 承载部门层级。
- 员工筛选、权限扩展和后续排班视图都会依赖本表。

```sql
CREATE TABLE department (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    workplace_id BIGINT,
    parent_id BIGINT,
    department_code VARCHAR(50),
    department_name VARCHAR(200) NOT NULL,
    sort_order INT DEFAULT 0,
    status VARCHAR(30) DEFAULT 'ACTIVE',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

第一阶段落地说明：

- 支持一级或多级部门。
- 第一阶段页面可先用树或列表 + 父部门选择器实现。

## 2.4 employee

用途：

- 承载员工主数据。
- 第一阶段员工管理、导入导出、后续排班、打卡、勤怠计算都依赖本表。

```sql
CREATE TABLE employee (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    workplace_id BIGINT,
    department_id BIGINT,
    employee_no VARCHAR(50) NOT NULL COMMENT '员工编号',
    employee_name VARCHAR(100) NOT NULL COMMENT '员工姓名',
    employee_name_kana VARCHAR(100),
    gender VARCHAR(20),
    employment_type VARCHAR(30) NOT NULL COMMENT '雇佣类型',
    hire_date DATE COMMENT '入社日',
    resign_date DATE COMMENT '退社日',
    email VARCHAR(100),
    phone VARCHAR(50),
    status VARCHAR(30) DEFAULT 'ACTIVE',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_tenant_employee_no (tenant_id, employee_no)
);
```

## 2.5 employee_work_rule

用途：

- 作为员工默认勤怠规则占位。
- 第一阶段只做默认规则初始化，不做复杂日本规则计算。

```sql
CREATE TABLE employee_work_rule (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    employee_id BIGINT NOT NULL,
    work_rule_type VARCHAR(50) NOT NULL COMMENT '勤務形態',
    standard_daily_minutes INT DEFAULT 480 COMMENT '标准日工时',
    standard_weekly_minutes INT DEFAULT 2400 COMMENT '标准周工时',
    overtime_enabled TINYINT DEFAULT 1,
    night_work_enabled TINYINT DEFAULT 1,
    holiday_work_enabled TINYINT DEFAULT 1,
    rounding_rule_id BIGINT,
    effective_start_date DATE NOT NULL,
    effective_end_date DATE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

第一阶段落地说明：

- 员工创建完成后可以自动补一条默认规则。
- 页面只提供轻量确认或编辑。

## 2.6 employee_external_mapping

用途：

- 建立员工与第三方打卡系统人员的映射关系。
- 是第三阶段打卡接收自动匹配员工的前置数据。

```sql
CREATE TABLE employee_external_mapping (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    employee_id BIGINT NOT NULL,
    source_system VARCHAR(50) NOT NULL COMMENT '外部系统',
    external_employee_id VARCHAR(100) NOT NULL COMMENT '外部系统员工ID',
    external_employee_no VARCHAR(100),
    status VARCHAR(30) DEFAULT 'ACTIVE',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_mapping (tenant_id, source_system, external_employee_id)
);
```

## 2.7 shift_template

用途：

- 维护可复用班次模板。
- 第二阶段排班时以模板为主，不让用户反复手输时间。

```sql
CREATE TABLE shift_template (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    template_code VARCHAR(50) NOT NULL,
    template_name VARCHAR(100) NOT NULL,
    shift_type VARCHAR(30) NOT NULL DEFAULT 'WORK',
    start_time TIME,
    end_time TIME,
    cross_day TINYINT DEFAULT 0 COMMENT '是否跨日',
    scheduled_break_minutes INT DEFAULT 0,
    color VARCHAR(30),
    is_active TINYINT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_shift_template_code (tenant_id, template_code)
);
```

## 3. 第一阶段接口设计

## 3.1 统一响应口径

第一阶段所有接口建议统一返回：

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {}
}
```

错误返回建议统一返回稳定业务码，例如：

- `TENANT_NOT_FOUND`
- `WORKPLACE_NOT_FOUND`
- `DEPARTMENT_NOT_FOUND`
- `EMPLOYEE_NOT_FOUND`
- `EMPLOYEE_NO_DUPLICATED`
- `SHIFT_TEMPLATE_CODE_DUPLICATED`
- `EXTERNAL_MAPPING_DUPLICATED`
- `VALIDATION_ERROR`

## 3.2 tenant 接口

```http
GET    /api/tenants/current
POST   /api/tenants/current
PUT    /api/tenants/current
```

说明：

- 第一阶段优先面向单租户初始化，不开放复杂租户列表管理。

## 3.3 workplace 接口

```http
GET    /api/workplaces
GET    /api/workplaces/{id}
POST   /api/workplaces
PUT    /api/workplaces/{id}
DELETE /api/workplaces/{id}
```

查询参数建议支持：

- `keyword`
- `status`

## 3.4 department 接口

```http
GET    /api/departments
GET    /api/departments/{id}
POST   /api/departments
PUT    /api/departments/{id}
DELETE /api/departments/{id}
```

查询参数建议支持：

- `workplaceId`
- `parentId`
- `status`

## 3.5 employee 接口

总文档已给出员工接口，第一阶段直接采用：

```http
GET    /api/employees
GET    /api/employees/{id}
POST   /api/employees
PUT    /api/employees/{id}
DELETE /api/employees/{id}
POST   /api/employees/import
GET    /api/employees/export
```

建议补充查询参数：

- `keyword`
- `departmentId`
- `workplaceId`
- `employmentType`
- `status`
- `hasExternalMapping`

## 3.6 employee_external_mapping 接口

```http
GET    /api/employees/{employeeId}/external-mappings
POST   /api/employees/{employeeId}/external-mappings
PUT    /api/employees/{employeeId}/external-mappings/{mappingId}
DELETE /api/employees/{employeeId}/external-mappings/{mappingId}
```

说明：

- 绑定入口挂在员工详情抽屉中。
- 第一阶段支持多个来源系统映射，但页面可先重点支持单条主映射维护。

## 3.7 shift_template 接口

总文档已给出班次模板 CRUD 接口：

```http
GET    /api/shift-templates
GET    /api/shift-templates/{id}
POST   /api/shift-templates
PUT    /api/shift-templates/{id}
DELETE /api/shift-templates/{id}
```

第一阶段建议补充：

```http
POST   /api/shift-templates/generate-recommended
```

用途：

- 一键生成早班、晚班、夜班、半日、休息、有休模板。

## 5. 第一阶段表与接口关系

```text
初始化向导
  ├─ 读取 tenant / workplace / department / employee / shift_template 数量
  ├─ 读取员工是否缺少 external mapping
  └─ 生成推荐下一步

员工管理
  ├─ employee CRUD
  ├─ employee import/export
  └─ employee_external_mapping CRUD

班次模板管理
  ├─ shift_template CRUD
  └─ generate-recommended

基础资料准备
  ├─ tenant CRUD
  ├─ workplace CRUD
  └─ department CRUD
```

## 6. 第一阶段实施建议

- 数据库初始化时建议预置一个默认租户，减少首次进入完全空系统的阻塞。
- 员工新增成功后建议自动写入一条默认 `employee_work_rule`。
- 推荐班次模板接口建议做到幂等：
  - 已存在同编码模板时不重复新增。
  - 可以返回新增数量和跳过数量。
- 初始化向导接口不要只返回数量，必须返回推荐下一步和页面跳转入口。
