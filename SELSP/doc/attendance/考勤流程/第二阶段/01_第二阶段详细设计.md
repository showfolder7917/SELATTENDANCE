# 日本通用勤怠排班系统 第二阶段详细设计

> 来源文档：`日本通用勤怠排班系统详细设计文档_v2_极限友好版.md`
> 适用阶段：`34.3 阶段 2：排班管理核心闭环`
> 适用工程：`SELATTENDANCE / SELSP + SELVUE`
> 设计前提：`第一阶段基础资料与初始化向导已完成，可直接进入排班管理核心闭环`

## 0. 当前实现问题与第二阶段起点

### 0.1 当前实现现状

- 第一阶段已经完成租户、事业所、部门、员工、外部打卡映射、班次模板和初始化向导闭环。
- 当前前端已经存在 `AttendanceWorkbenchView` 单工作台骨架、左侧导航、右侧主工作区、中日双语字典、主题切换和空状态引导。
- 当前后端已经形成 `attendance/tenant`、`attendance/workplace`、`attendance/department`、`attendance/employee`、`attendance/shifttemplate`、`attendance/bootstrap` 的子域化结构。
- 当前系统已经具备“排班前主数据完整”的前置条件，但还没有真正让管理员开始排班。

### 0.2 当前核心缺口

- 问题 1：管理员已经能维护员工和班次模板，但还不能把模板真正安排到员工日期上。
- 问题 2：初始化向导第 6 步“开始排班”仍是锁定占位，用户完成第一阶段后会停在“知道该排班，但没有排班入口”的状态。
- 问题 3：总文档已经定义了排班模块和极限友好页面，但当前工程还没有把“第二阶段可直接开发的排班闭环”拆成单独执行稿。
- 问题 4：如果第二阶段直接上复杂打卡和日次计算，会把第三、四阶段能力提前混入排班阶段，增加实现和联调噪音。

### 0.3 第二阶段必须沿用的现有规范

- 前端继续沿用单工作台模式，不新增独立后台路由体系。
- 前端继续沿用 `src/services/request.js` 作为共享请求底座。
- 前端继续沿用 `src/services/attendance/*`、`src/components/attendance/*`、`src/composables/attendance/*`、`src/constants/i18nMessages.js` 的结构。
- 后端继续沿用 `com.sp.selfsp.attendance.<subdomain>` 的子域化结构，不回退到已清理掉的旧 `attendance/controller|dao|service` 平铺目录。
- 页面继续保持中日双语、空状态引导、推荐下一步、人类可读提示和主题切换能力。

### 0.4 第二阶段开发前必须明确的边界

1. 第二阶段只完成“排班计划”闭环，不进入打卡事实接收。
2. 第二阶段只保存和展示 `shift_schedule`，不生成 `punch_raw_log`、`attendance_daily`、`attendance_monthly`。
3. 第二阶段允许预留锁定字段和备注，但不实现月结锁定、审批流和日本高级工时规则。
4. 第二阶段优先让管理员“看懂并快速排班”，而不是优先做复杂批处理能力。

## 1. 目标

第二阶段的目标是把第一阶段准备好的员工和班次模板，真正转换为“可发布、可检查、可批量维护”的排班计划。

第二阶段完成后，用户应当能够：

- 按月份查看员工排班日历。
- 按部门、事业所、员工筛选排班对象。
- 给单个员工单日排班。
- 批量给多个员工在日期范围内排班。
- 复制上一周或上一月排班。
- 清空单日排班或整段排班。
- 检查哪些员工、哪些日期仍然未排班。
- 在覆盖已有排班前看到明确确认提示。
- 在没有员工或没有班次模板时，直接看到去补数据的入口。
- 在初始化向导和工作台中看到“第二阶段已开始”的进度反馈。

## 2. 输入与输出边界

### 2.1 输入

第二阶段主要输入来源如下：

- 第一阶段已落地的员工主数据。
- 第一阶段已落地的部门和事业所主数据。
- 第一阶段已落地的班次模板数据。
- 管理员在排班页面上的单点、批量、复制类操作。
- 前端当前语言 `zh-CN / ja-JP`。

第二阶段主输入字段包括：

- 排班筛选：
  - 年月
  - 事业所
  - 部门
  - 员工关键字
  - 是否只看未排班
- 单日排班：
  - 员工 ID
  - 工作日期
  - 班次模板 ID
  - 备注
- 批量排班：
  - 员工 ID 列表
  - 日期范围
  - 班次模板 ID
  - 是否跳过已有排班
  - 是否覆盖已有排班
  - 备注
- 复制排班：
  - 来源日期范围
  - 目标日期范围
  - 员工范围
  - 是否覆盖已有排班
- 清空排班：
  - 员工 ID
  - 日期或日期范围

### 2.2 输出

第二阶段输出对象如下：

- 已落库的 `shift_schedule` 排班计划数据。
- 可按员工、部门、月份查看的排班日历视图。
- 未排班统计和冲突提示结果。
- 批量排班和复制排班的预览与执行结果。
- 初始化向导第 6 步的可进入状态。

第二阶段输出限制如下：

- 不输出原始打卡记录。
- 不输出日次勤怠计算结果。
- 不输出月次汇总结果。
- 不输出审批流结果。
- 不输出有休台账结果。

## 3. 核心设计原则

- 原则 1：第二阶段先把“计划”做好，不提前混入“事实”和“计算”。
- 原则 2：管理员优先通过班次模板排班，不让用户反复手输具体时间。
- 原则 3：排班页面必须像可操作日历，不允许只给一张难读的大表。
- 原则 4：任何覆盖、复制、清空操作都必须先预览或至少明确提示风险。
- 原则 5：没有员工、没有班次模板、没有部门时，页面必须直接给出补数据入口。
- 原则 6：第二阶段所有状态、按钮、图例、警告、抽屉、向导仍然必须支持中日双语。
- 原则 7：结构上继续沿用现有 `attendance` 子域和工作台分区，不重新设计一套新框架。

## 4. 方案设计

### 4.1 第二阶段总体方案

第二阶段按“工作台新增排班分区 + 排班日历 + 批量排班向导”的模式落地。

主流程如下：

```text
进入第一阶段工作台
  ↓
第 6 步“开始排班”从锁定占位变为可进入
  ↓
进入排班管理分区
  ↓
按年月 / 部门 / 员工筛选要排班的对象
  ↓
从右侧班次模板面板选择班次
  ↓
点击日历格子给员工排班
  ↓
对缺失区域使用批量排班或复制上周
  ↓
检查未排班员工和冲突
  ↓
保存后形成第二阶段排班基础数据
```

### 4.2 工作台承接方式

第二阶段不再新起一个风格完全不同的页面，而是直接承接当前工作台：

- 左侧导航新增 `排班管理 / シフト作成` 分区。
- 初始化向导中的第 6 步从“下一阶段开放”改为“进入排班管理”。
- 顶部继续保留：
  - 页面标题
  - 页面说明
  - 语言切换
  - 主题切换
- 内容区继续采用“模块头 + 主工作区”的结构，减少用户学习成本。

### 4.3 排班管理页面设计

排班管理页面必须满足以下布局：

- 顶部工具条：
  - 年月切换
  - 事业所筛选
  - 部门筛选
  - 员工关键字检索
  - 只看未排班开关
  - 复制上周
  - 复制上月
  - 批量排班
  - 导出排班表
- 左侧固定区：
  - 员工列表
  - 员工编号
  - 员工姓名
  - 部门
  - 未排班天数标签
- 中间主区：
  - 月视图排班日历
  - 周视图切换入口
  - 每个日期格显示班次名称、时间、状态
- 右侧辅助区：
  - 班次模板面板
  - 图例说明
  - 今日操作提示
  - 当前选中员工 / 当前选中日期说明
- 底部反馈区：
  - 保存结果
  - 冲突提醒
  - 未排班提醒

### 4.4 排班单元格设计

每个排班格子至少显示：

```text
日期
星期
班次名称
时间范围
状态标记
```

状态标记要求：

- 未排班：虚线边框 + 淡黄色底
- 工作班次：按模板颜色显示标签
- 休息：灰色标签
- 有休：绿色或紫色标签
- 夜班：深蓝标签
- 已锁定预留：锁图标
- 有备注：角标提示

### 4.5 交互方式设计

页面至少支持以下交互：

1. 先点右侧班次模板，再点日历格子即可排班。
2. 点击已有排班格子，可以打开右侧详情卡查看并修改。
3. 右键或更多菜单可以执行清空、复制到其他日期、添加备注。
4. 批量排班通过向导完成，不允许让用户一次性填写大表单。
5. 复制上周、复制上月必须先给预览摘要，再确认保存。

### 4.6 批量排班向导设计

批量排班向导按 5 步落地：

```text
第 1 步：选择员工范围
第 2 步：选择日期范围
第 3 步：选择班次模板
第 4 步：预览覆盖范围、未排班填充范围和冲突数量
第 5 步：确认保存
```

每一步必须显示：

- 当前步骤标题
- 简单一句人话说明
- 已选内容摘要
- 返回上一步按钮
- 进入下一步按钮

### 4.7 极度友好的页面要求

第二阶段页面必须明确满足以下体验要求：

- 第一次进入排班页面，如果一个排班都没有，直接显示：
  - `这个月还没有排班`
  - `你可以从右侧选择班次，然后点击日期格子安排班次`
  - `复制上周排班`
  - `批量排班`
  - `单个员工排班`
- 如果没有员工：
  - 不显示空日历主体
  - 直接提示先去员工管理补数据
- 如果没有班次模板：
  - 直接提示先去班次模板区创建或一键生成推荐模板
- 覆盖已有排班时必须弹出确认：
  - 当前已有班次是什么
  - 将被替换成什么
  - 影响几个日期
- 未排班检查必须做人类可读结果：
  - 哪些员工完全未排班
  - 哪些日期仍为空
  - 下一步建议是什么

### 4.8 双语与视觉要求

第二阶段继续沿用当前项目的双语和主题口径：

- 所有页面文案统一写入 `src/constants/i18nMessages.js`。
- 保持 `zh-CN` 与 `ja-JP` 一键切换。
- 排班图例、批量向导步骤名、冲突提示、未排班提醒都必须双语。
- 视觉层继续复用当前工作台的：
  - `seladmin-*` 基础外壳
  - `AttendanceSectionNav`
  - `ResizableWorkbenchSplit`
  - 主题预设切换
- 不引入额外 UI 组件库，不改变第一阶段已经形成的界面语气。

## 5. 数据与字段设计

### 5.1 第二阶段必须新增的数据对象

- `shift_schedule`

### 5.2 shift_schedule 表设计

用途：

- 保存员工按日维度的排班结果。
- 作为第三阶段打卡匹配、第四阶段日次计算的计划来源。

```sql
CREATE TABLE shift_schedule (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    employee_id BIGINT NOT NULL,
    work_date DATE NOT NULL COMMENT '勤怠日期',
    shift_template_id BIGINT,
    scheduled_start_time DATETIME,
    scheduled_end_time DATETIME,
    scheduled_break_minutes INT DEFAULT 0,
    work_day_type VARCHAR(30) DEFAULT 'WORKDAY',
    status VARCHAR(30) DEFAULT 'ACTIVE',
    locked TINYINT DEFAULT 0,
    remark VARCHAR(500),
    created_by BIGINT,
    updated_by BIGINT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_employee_work_date (tenant_id, employee_id, work_date)
);
```

### 5.3 work_day_type 枚举建议

```text
WORKDAY          出勤日
LEGAL_HOLIDAY    法定休日
COMPANY_HOLIDAY  所定休日
PAID_LEAVE       有給
SPECIAL_LEAVE    特別休暇
ABSENCE          欠勤
REST             休み
```

### 5.4 第二阶段字段收敛原则

- `locked` 字段本阶段只预留，不做完整锁定流程。
- `remark` 允许记录排班备注，但不做复杂审批用途。
- `scheduled_start_time`、`scheduled_end_time`、`scheduled_break_minutes` 在保存时从班次模板展开，避免第三阶段联表过重。
- 第二阶段不新增打卡来源、审批状态、计算结果字段。

## 7. 风险点

- 风险 1：如果第二阶段把打卡导入一起做进去，会打破“计划先于事实”的阶段边界。
- 风险 2：如果排班页面直接要求用户输入具体时间，会让第一阶段班次模板的价值消失。
- 风险 3：如果批量排班不做预览和覆盖提示，管理员很容易一次性改坏整月数据。
- 风险 4：如果未排班检查不提供明确结果，用户会不知道哪些员工和日期仍需处理。
- 风险 5：如果第二阶段脱离现有工作台单独起新页面，第一阶段形成的操作习惯会被打断。

## 8. 验证方案

### 8.1 主路径验证

- 可以查看指定月份的员工排班日历。
- 可以给单个员工单日排班。
- 可以修改已有排班。
- 可以清空单日排班。
- 可以批量给多个员工在日期范围内排班。
- 可以复制上周排班并保存。
- 可以复制上月排班并保存。
- 可以查看未排班员工和日期。

### 8.2 页面体验验证

- 第一次进入空排班页面时，可以看到明确的引导卡。
- 没有员工时，页面能直接提示去员工管理补数据。
- 没有班次模板时，页面能直接提示去班次模板区补数据。
- 覆盖已有排班前会出现确认弹窗。
- 批量排班向导每一步都有清楚的步骤说明和已选摘要。
- 页面可以一键切换中文 / 日语。

### 8.3 通过标准

- `shift_schedule` 数据可正确持久化。
- 月视图排班可以直观展示班次名称和时间。
- 批量排班、复制上周、复制上月主路径可用。
- 未排班检查结果可读、可定位、可回到对应员工和日期。
- 第二阶段页面延续第一阶段工作台体验，不出现纯技术化难读界面。
